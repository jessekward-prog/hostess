Install on your machine

Pick your operating system. Every installer is idempotent: safe to run on a brand-new machine and safe to re-run later.

Debian / Ubuntu family · apt + user systemd service
Quick install (Bash) Installs git if missing, clones to ~/hostess, and runs install.sh
install.sh ↗
$ 
(command -v git >/dev/null 2>&1 || (sudo apt-get update -y && sudo apt-get install -y git)) && (git clone --depth 1 https://github.com/jessekward-prog/hostess.git ~/hostess || git -C ~/hostess pull --ff-only) && ~/hostess/install.sh

What happens when you run it

Mostly unattended. Here is every prompt you will see on a clean machine:

  • Step 01 Terminal asks for your sudo password once to install missing packages via apt and Docker's official repository.
  • Step 02 First run only: if Docker was just installed, log out and back in so your new docker group membership takes effect, then re-run the command.
  • Step 03 Ready when it prints http://localhost:5300 and opens the dashboard in your browser.

What it sets up

Ensures Docker, Node.js 18+, git, and curl are installed. Clones to ~/hostess, registers a user-level hostess.service with loginctl enable-linger so it survives reboot and logout, and adds an hourly hostess-update.timer that only restarts the server when a new commit lands on main.

1. Docker, Node.js 20, git

sudo apt-get update -y && sudo apt-get install -y git curl ca-certificates
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt-get install -y nodejs
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"

2. Clone + install dependencies

git clone --depth 1 https://github.com/jessekward-prog/hostess.git ~/hostess
cd ~/hostess && npm install --omit=dev

3. User systemd service

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/hostess.service <<EOF
[Unit]
Description=Hostess dashboard
After=network.target docker.service

[Service]
WorkingDirectory=%h/hostess
ExecStart=$(command -v node) server.js
Restart=on-failure

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload
systemctl --user enable --now hostess
loginctl enable-linger "$USER"

4. Service control

systemctl --user status  hostess
systemctl --user restart hostess
systemctl --user stop    hostess
Quick install (macOS) Checks Xcode CLI Tools, clones to ~/hostess, runs install-macos.sh
install-macos.sh ↗
% 
if ! xcode-select -p >/dev/null 2>&1; then xcode-select --install; echo "Approve the Command Line Tools dialog, then re-run this command."; else (git clone --depth 1 https://github.com/jessekward-prog/hostess.git ~/hostess || git -C ~/hostess pull --ff-only) && ~/hostess/install-macos.sh; fi

What happens when you run it

Works on Apple Silicon and Intel Macs. Here is what it asks of you:

  • Step 01 If macOS Command Line Tools aren't installed yet, macOS pops up an install dialog. Approve it, then re-run the command.
  • Step 02 Terminal asks for your Mac login password once for Homebrew and Docker Desktop installation.
  • Step 03 Docker Desktop's first launch shows a permissions dialog. Approve it (no Docker Hub account required), and your browser opens to http://localhost:5300.

What it sets up

Installs Homebrew if missing, followed by git, node, and Docker Desktop. Clones to ~/hostess and registers a launchd agent (xyz.cmdward.hostess.plist) with full Homebrew/Docker PATH plus an hourly update agent that only restarts when upstream commits change.

1. Homebrew, git, Node, Docker Desktop

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install git node
brew install --cask docker
open -a Docker

2. Clone + install dependencies

git clone --depth 1 https://github.com/jessekward-prog/hostess.git ~/hostess
cd ~/hostess && npm install --omit=dev

3. launchd agent

cat > ~/Library/LaunchAgents/xyz.cmdward.hostess.plist <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<plist version="1.0"><dict>
  <key>Label</key><string>xyz.cmdward.hostess</string>
  <key>ProgramArguments</key>
  <array><string>$(command -v node)</string><string>server.js</string></array>
  <key>WorkingDirectory</key><string>$HOME/hostess</string>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>EnvironmentVariables</key>
  <dict>
    <key>PATH</key><string>$HOME/.docker/bin:/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin</string>
  </dict>
</dict></plist>
EOF
launchctl load -w ~/Library/LaunchAgents/xyz.cmdward.hostess.plist

4. Service control

launchctl unload ~/Library/LaunchAgents/xyz.cmdward.hostess.plist
launchctl load -w ~/Library/LaunchAgents/xyz.cmdward.hostess.plist
Quick install (PowerShell) Self-elevates via UAC, installs prerequisites via winget, and starts Hostess
install.ps1 ↗
PS> 
iwr -useb https://raw.githubusercontent.com/jessekward-prog/hostess/main/install.ps1 | iex

What happens when you run it

Paste into any PowerShell window (Start menu, type "PowerShell"):

  • Step 01 A UAC prompt appears. Click Yes; a new elevated PowerShell window opens and runs the installation.
  • Step 02 If WSL2 was never enabled on this PC, it enables WSL2 and asks you to reboot once, then paste the same command again.
  • Step 03 Accept Docker Desktop's first-run license dialog (skip Docker Hub sign-in). Your browser opens to http://localhost:5300 once Docker is ready.

What it sets up

Installs Git.Git, OpenJS.NodeJS.LTS (18+), and Docker.DockerDesktop via winget. Clones to $HOME\hostess and registers a logon Scheduled Task with automatic restart-on-failure plus an hourly update check.

1. git, Node.js LTS, Docker Desktop

winget install --id Git.Git -e
winget install --id OpenJS.NodeJS.LTS -e
winget install --id Docker.DockerDesktop -e

2. Enable WSL2

wsl --install --no-distribution

3. Clone + install dependencies

git clone --depth 1 https://github.com/jessekward-prog/hostess.git $HOME\hostess
cd $HOME\hostess
npm install --omit=dev

4. Scheduled Task

$action = New-ScheduledTaskAction -Execute "powershell.exe" `
  -Argument '-NoProfile -WindowStyle Hidden -Command "while ($true) { Set-Location $HOME\hostess; node server.js; Start-Sleep -Seconds 2 }"'
$trigger = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
Register-ScheduledTask -TaskName hostess -Action $action -Trigger $trigger -Force
Start-ScheduledTask -TaskName hostess

5. Service control

Start-ScheduledTask -TaskName hostess
Stop-ScheduledTask  -TaskName hostess

What Hostess wires automatically

Apps declare what they need in app.yaml or source code; Hostess provisions the backing containers, networks, and secrets at deploy time.

Shared Postgres postgres: true

Creates an isolated SQL role and database on selfhost-postgres (selfhost-net) and injects both DATABASE_URL and discrete DB_* variables. Redeploys reuse the existing role password.

Isolated Web Search search: true

Provisions a shared SearXNG instance on a dedicated hostess-search network (no route to Postgres) and injects SEARXNG_URL for JSON search queries.

Local AI Auto-Link Auto-detected

Scans JS/TS source for LM_STUDIO_URL, LM_STUDIO_API_KEY, and LM_STUDIO_MODEL and injects your MY AI library endpoint automatically without editing app.yaml.

Private Push Server Auto-detected

Apps reading NTFY_URL, NTFY_TOKEN, and NTFY_TOPIC are joined to hostess-push, a built-in ntfy server published privately to your phone over Tailscale.

Pre-Build Security Guard Every deploy

Before docker build runs, your local AI reviews the repo's Dockerfile, app.yaml, and entrypoint for privileged flags, remote script execution, or exposed secrets.

Forge & Marketplace Built in

Install curated apps from the Marketplace in one click, or describe a new app in Forge (/forge.html) to generate, test-drive, and deploy it locally.

Deploying an app

Every deployable repository has a Dockerfile and an app.yaml at its root.

app.yaml schema

name: my-app
port: 3000
postgres: false
search: false
autoUpdate: true
dataDir: /app/data
description: "Short blurb shown on the card"
icon: public/icon.svg
env: []
  • nameLowercase letters, numbers, and hyphens (2 to 50 chars).
  • portContainer port the app listens on (bind 0.0.0.0, not localhost). Hostess does not inject PORT.
  • postgresProvisions a role + database and injects DATABASE_URL + DB_*.
  • searchAttaches hostess-search and injects SEARXNG_URL.
  • dataDirAbsolute container path persisted across redeploys in a named Docker volume.
  • autoUpdatePolls git remotes every 10 minutes and redeploys on new commits.
  • publicGatewayOptional { port: 3001 } for narrow token-gated share links via /run/hostess-gateway/url.
  • envExtra env var names exposed on the card's reveal panel (AI, APP_PIN, and NTFY_* are auto-detected in JS/TS).

Deploy from UI or CLI

Paste any GitHub URL or local directory path into the dashboard on localhost:5300, or deploy from a terminal:

# Deploy from a GitHub repository
node deploy.js https://github.com/you/your-app

# Deploy from a local directory on disk
node deploy.js /path/to/local/repo

Lifecycle & live AI model switching

Redeploying the same app name reuses its assigned host port, container name, persistent dataDir volume, and Postgres password.

Every app that reads LM_STUDIO_* receives your fleet AI settings at deploy time. Apps that also implement the optional GET/PUT /api/lm contract (protected by SYNC_SECRET) get a live Local / Claude provider and model switcher right on their dashboard card without needing a container restart.
