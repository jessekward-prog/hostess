Linux

Debian / Ubuntu-family — apt + a user-level systemd service

Quick install

One command. Works on a clean machine, safe to re-run.

curl -fsSL https://raw.githubusercontent.com/jessekward-prog/selfhost-wizard/main/install.sh | bash
view source ↗

What it sets up

Installs Docker, Node.js 18+, and git if missing (adds you to the docker group — log out/in after). Clones to ~/selfhost-wizard and registers a systemd user service so the dashboard survives reboot and logout.

1Docker, Node, git

sudo apt-get update -y && sudo apt-get install -y git curl -fsSL https://get.docker.com | sudo sh sudo usermod -aG docker "$USER"

2Clone + install

git clone --depth 1 https://github.com/jessekward-prog/selfhost-wizard.git ~/selfhost-wizard cd ~/selfhost-wizard && npm install --omit=dev

3systemd service

mkdir -p ~/.config/systemd/user cat > ~/.config/systemd/user/selfhost-wizard.service <<EOF [Unit] Description=Self-Host Wizard dashboard After=network.target docker.service [Service] WorkingDirectory=%h/selfhost-wizard ExecStart=$(command -v node) server.js Restart=on-failure [Install] WantedBy=default.target EOF systemctl --user daemon-reload systemctl --user enable --now selfhost-wizard loginctl enable-linger "$USER"

4Manage it

systemctl --user status selfhost-wizard systemctl --user restart selfhost-wizard systemctl --user stop selfhost-wizard

macOS

Apple Silicon or Intel — Homebrew + a launchd agent

Quick install

One command. Works on a clean machine, safe to re-run.

curl -fsSL https://raw.githubusercontent.com/jessekward-prog/selfhost-wizard/main/install-macos.sh | bash
view source ↗

What it sets up

Installs Homebrew if missing, then git/node/Docker Desktop. Docker's first run needs you to click through its permissions dialog. Clones to ~/selfhost-wizard and registers a launchd agent so the dashboard survives reboot and logout.

1Homebrew, git, node, Docker

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)" brew install git node brew install --cask docker open -a Docker

2Clone + install

git clone --depth 1 https://github.com/jessekward-prog/selfhost-wizard.git ~/selfhost-wizard cd ~/selfhost-wizard && npm install --omit=dev

3launchd agent

cat > ~/Library/LaunchAgents/xyz.cmdward.selfhost-wizard.plist <<EOF <?xml version="1.0" encoding="UTF-8"?> <plist version="1.0"><dict> <key>Label</key><string>xyz.cmdward.selfhost-wizard</string> <key>ProgramArguments</key> <array><string>$(command -v node)</string><string>server.js</string></array> <key>WorkingDirectory</key><string>$HOME/selfhost-wizard</string> <key>RunAtLoad</key><true/> <key>KeepAlive</key><true/> </dict></plist> EOF launchctl load -w ~/Library/LaunchAgents/xyz.cmdward.selfhost-wizard.plist

4Manage it

launchctl unload ~/Library/LaunchAgents/xyz.cmdward.selfhost-wizard.plist launchctl load -w ~/Library/LaunchAgents/xyz.cmdward.selfhost-wizard.plist

Windows

PowerShell — winget + a Scheduled Task, self-elevates via UAC

Quick install

Run in PowerShell (Start → type "PowerShell"). Approve the UAC prompt.

iwr -useb https://raw.githubusercontent.com/jessekward-prog/selfhost-wizard/main/install.ps1 | iex
view source ↗

What it sets up

Installs git/Node LTS/Docker Desktop via winget, enables WSL2 if needed (a truly clean machine needs one reboot here — Docker's requirement, not this script's). Clones to $HOME\selfhost-wizard and registers a Scheduled Task so the dashboard survives reboot.

1git, Node, Docker Desktop

winget install --id Git.Git -e winget install --id OpenJS.NodeJS.LTS -e winget install --id Docker.DockerDesktop -e

2WSL2

wsl --install --no-distribution

If this just installed it, reboot Windows and re-run the installer — it stops cleanly and tells you this.

3Clone + install

git clone --depth 1 https://github.com/jessekward-prog/selfhost-wizard.git $HOME\selfhost-wizard cd $HOME\selfhost-wizard npm install --omit=dev

4Scheduled Task

$action = New-ScheduledTaskAction -Execute "powershell.exe" ` -Argument '-NoProfile -WindowStyle Hidden -Command "Set-Location $HOME\selfhost-wizard; node server.js"' $trigger = New-ScheduledTaskTrigger -AtLogOn Register-ScheduledTask -TaskName selfhost-wizard -Action $action -Trigger $trigger -Force Start-ScheduledTask -TaskName selfhost-wizard

5Manage it

Start-ScheduledTask -TaskName selfhost-wizard Stop-ScheduledTask -TaskName selfhost-wizard

Deploying an app

Once it's running, point it at any repo with a Dockerfile + app.yaml at its root

app.yaml

name: my-app port: 3000 postgres: false env: []
  • name lowercase letters/numbers/hyphens, 2-50 chars
  • port what your app listens on inside the container
  • postgres true wires a DATABASE_URL + DB_* vars to a shared Postgres
  • env documents required var names (see Known limitations)

Deploy it

Paste the repo URL (or a local path) into the dashboard, or from the CLI:

node deploy.js https://github.com/you/your-app node deploy.js /path/to/local/repo

Redeploying the same app name reuses its host port, container name, and — for Postgres apps — its existing role password.

Known limitations

app.yaml's env list isn't injected yet — it's parsed and stored, but nothing collects values for it or passes them to the container. The only env variable actually set today is DATABASE_URL / DB_* (when postgres: true). Give your app its own way to set config post-deploy — an admin UI backed by its own DB, for example — rather than relying on env: to deliver secrets.
