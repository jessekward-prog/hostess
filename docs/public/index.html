hostess

One command turns a clean machine into a self-hosted app platform. Point hostess at any repo with an app.yaml and it builds, deploys, and manages it in Docker for you.

Linux

Debian / Ubuntu-family — apt + a user-level systemd service

Quick install

One command. Works on a clean machine, safe to re-run.

curl -fsSL https://raw.githubusercontent.com/jessekward-prog/hostess/main/install.sh | bash
view source ↗

What to expect

Mostly unattended — this is everything it'll ask of you.

1Terminal asks for your sudo password once, for the apt/Docker installs.

2First time only: log out and back in so your new docker group membership takes effect, then re-run the command.

3Done when it prints the dashboard URL and opens it in your browser.

What it sets up

Installs Docker, Node.js 18+, and git if missing (adds you to the docker group — log out/in after). Clones to ~/hostess and registers a systemd user service so the dashboard survives reboot and logout.

1Docker, Node, git

sudo apt-get update -y && sudo apt-get install -y git curl -fsSL https://get.docker.com | sudo sh sudo usermod -aG docker "$USER"

2Clone + install

git clone --depth 1 https://github.com/jessekward-prog/hostess.git ~/hostess cd ~/hostess && npm install --omit=dev

3systemd service

mkdir -p ~/.config/systemd/user cat > ~/.config/systemd/user/hostess.service <<EOF [Unit] Description=Hostess dashboard After=network.target docker.service [Service] WorkingDirectory=%h/hostess ExecStart=$(command -v node) server.js Restart=on-failure [Install] WantedBy=default.target EOF systemctl --user daemon-reload systemctl --user enable --now hostess loginctl enable-linger "$USER"

4Manage it

systemctl --user status hostess systemctl --user restart hostess systemctl --user stop hostess

macOS

Apple Silicon or Intel — Homebrew + a launchd agent

Quick install

One command. Works on a clean machine, safe to re-run.

curl -fsSL https://raw.githubusercontent.com/jessekward-prog/hostess/main/install-macos.sh | bash
view source ↗

What to expect

This is everything it'll ask of you.

1Terminal asks for your Mac login password once, for Homebrew/installs.

2Docker Desktop's first launch shows a permissions dialog — approve it. No account/sign-in needed.

3Done when it prints the dashboard URL and opens it in your browser.

What it sets up

Installs Homebrew if missing, then git/node/Docker Desktop. Docker's first run needs you to click through its permissions dialog. Clones to ~/hostess and registers a launchd agent so the dashboard survives reboot and logout.

1Homebrew, git, node, Docker

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)" brew install git node brew install --cask docker open -a Docker

2Clone + install

git clone --depth 1 https://github.com/jessekward-prog/hostess.git ~/hostess cd ~/hostess && npm install --omit=dev

3launchd agent

cat > ~/Library/LaunchAgents/xyz.cmdward.hostess.plist <<EOF <?xml version="1.0" encoding="UTF-8"?> <plist version="1.0"><dict> <key>Label</key><string>xyz.cmdward.hostess</string> <key>ProgramArguments</key> <array><string>$(command -v node)</string><string>server.js</string></array> <key>WorkingDirectory</key><string>$HOME/hostess</string> <key>RunAtLoad</key><true/> <key>KeepAlive</key><true/> </dict></plist> EOF launchctl load -w ~/Library/LaunchAgents/xyz.cmdward.hostess.plist

4Manage it

launchctl unload ~/Library/LaunchAgents/xyz.cmdward.hostess.plist launchctl load -w ~/Library/LaunchAgents/xyz.cmdward.hostess.plist

Windows

PowerShell — winget + a Scheduled Task, self-elevates via UAC

Quick install

Run in PowerShell (Start → type "PowerShell"). Approve the UAC prompt.

iwr -useb https://raw.githubusercontent.com/jessekward-prog/hostess/main/install.ps1 | iex
view source ↗

What to expect

This is everything it'll ask of you — leave the new window open, it's doing the work.

1A UAC prompt appears — click Yes. A new elevated PowerShell window opens; that's the real install running, not a second copy.

2Docker Desktop's first launch shows a license dialog — click Accept. It may also offer to sign in to Docker Hub — skip that, it's optional.

3If it says WSL2 needs a reboot, restart and paste the same command again — it picks up where it left off.

4Done when your browser opens itself to the dashboard.

What it sets up

Installs git/Node LTS/Docker Desktop via winget, enables WSL2 if needed (a truly clean machine needs one reboot here — Docker's requirement, not this script's). Clones to $HOME\hostess and registers a Scheduled Task so the dashboard survives reboot.

1git, Node, Docker Desktop

winget install --id Git.Git -e winget install --id OpenJS.NodeJS.LTS -e winget install --id Docker.DockerDesktop -e

2WSL2

wsl --install --no-distribution

If this just installed it, reboot Windows and re-run the installer — it stops cleanly and tells you this.

3Clone + install

git clone --depth 1 https://github.com/jessekward-prog/hostess.git $HOME\hostess cd $HOME\hostess npm install --omit=dev

4Scheduled Task

$action = New-ScheduledTaskAction -Execute "powershell.exe" ` -Argument '-NoProfile -WindowStyle Hidden -Command "Set-Location $HOME\hostess; node server.js"' $trigger = New-ScheduledTaskTrigger -AtLogOn Register-ScheduledTask -TaskName hostess -Action $action -Trigger $trigger -Force Start-ScheduledTask -TaskName hostess

5Manage it

Start-ScheduledTask -TaskName hostess Stop-ScheduledTask -TaskName hostess

Deploying an app

Once it's running, point it at any repo with a Dockerfile + app.yaml at its root

app.yaml

name: my-app port: 3000 postgres: false autoUpdate: false env: []
  • name lowercase letters/numbers/hyphens, 2-50 chars
  • port what your app listens on inside the container
  • postgres true wires a DATABASE_URL + DB_* vars to a shared Postgres
  • autoUpdate true redeploys automatically when the source repo gets a new commit (checked every ~10 min)
  • env each name gets its own reveal panel on the app card — set a value there and it's wired in via docker run -e on redeploy, no manual env file editing

Deploy it

Paste the repo URL (or a local path) into the dashboard, or from the CLI:

node deploy.js https://github.com/you/your-app node deploy.js /path/to/local/repo

Redeploying the same app name reuses its host port, container name, and — for Postgres apps — its existing role password.

Known limitations

The Local/Claude AI toggle on an app card only appears if that app implements its own GET/PUT /api/lm, protected by a SYNC_SECRET env var (contract documented in the repo README). Apps that don't implement it show no toggle at all — there's no generic fallback yet, so wiring AI into an app currently means building that endpoint into it, not just flipping a switch.
